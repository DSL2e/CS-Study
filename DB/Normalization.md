## 정규화의 목적

관계 스키마에서 나타내는 중복데이터를 줄일 수 있다

불필요한 중복을 제거하기 위한 스키마 변환 방법을 제공

무결성 보장, 정확성, 일관성 유지

→ 하지만 조인, 테이블 수가 증가

### 이상현상(Anomaly) : 정규화되지 않은 테이블에서 발생할 수 있는 현상들

삭제 이상 : 데이터 삭제시 다른 데이터까지 삭제되는 현상. 

- 이승우 고객이 제품A를 주문한 유일한 고객일 때 → 이승우 고객이 이 주문을 취소한다면 제품에 대한 정보도 삭제됨

삽입 이상 : NULL을 넣어야 하는 현상

- 주문이 없는 제품에 대한 주문정보는 저장될 수 없음.
- 불필요한 데이터까지 NULL로 삽입해야하는 문제

갱신 이상 : 수정했을 때 같은 값을 참조해야하는 데이터들이 달라지는 현상

- 따라서 이승우 고객의 주소가 변경된다면 모든 튜플을 찾아 갱신해야함.

## 반정규화

정규화는 이전의 문제점을 모두 해결하긴 했지만 성능에 영향을 주는 trade-off 발생

→ 시스템의 성능 향상, 개발, 운영의 단순화를 위해 정규화된 데이터 모델을 반대로 통합, 중복 관리하는 모델링 기법인 반정규화 등장

ex) sns 좋아요 테이블

테이블이 단순화됨 → 읽는 성능은 향상시키지만, 삽입, 수정, 삭제 성능은 낮아진다.

반정규화를 통해 오류나 비일관성, 비정확성 등의 문제가 발생할 가능성이 있기 때문에 비판적 시각이 존재

### 반정규화의 이점

자주 쓰이는 데이터들을 테이블 별로 분리 해놓는 것보단 한 테이블에 통합함으로서 조인 연산 생략

→ 복잡한 쿼리 필요X, db 부하 감소

### 반정규화 절차

`반정규화에 따른 장점은 명확하지만 그에 따른 단점 또한 명확하기에 적용하기 전 충분한 고민이 필요함`

1. 대상 조사
    - 범위 처리 빈도수 조사
    - 대량 데이터 범위 처리 조사
    - 통계성 프로세스 조사
    - 테이블 조인 조사
2. 개선 방법 탐색
    - View - 자주 쓰이는 데이터를 View로 생성
    - 클러스터링 - 묶어서 저장
    - 인덱스 - 인덱스 변경 및 생성
3. 반정규화 적용
    - 테이블 반정규화 - 테이블 병합, 수평분할, 수직분할
    - 컬럼 반정규화 - 중복 컬럼, 파생컬럼, 이력 컬럼 추가
    - 관계 반정규화 - 중복관계 추가

## 반정규화 방법

- `테이블 병합`
    - 1:1 관계 테이블 병합 : 1:1 관계를 통합하여 성능향상

        <img width="484" alt="image (6)" src="https://github.com/user-attachments/assets/ab912791-84ad-4bf9-bfbc-65e192d691e3">


    - 1:M 관계 테이블 병합 : 1:M 관계를 통합하여 성능향상

      <img width="474" alt="image (7)" src="https://github.com/user-attachments/assets/55d6c99b-c5ce-4779-b571-e2bcf84b329f">

        
    - 슈퍼/서브타입 테이블병합 : 슈퍼/서브 관계를 통합하여 성능향상
- `테이블 분할` (1:1대응 관계일 때?)
    - 수직분할 : 하나의 테이블의 속성을 분할하여 두 개 이상의 테이블로 분할
        - 한 테이블에 속성이 너무 많은 경우

        <img width="406" alt="image (8)" src="https://github.com/user-attachments/assets/c0467134-b8d3-4990-bad2-e3e405af66ed">


    - 수평분할 : 하나의 테이블에 있는 값을 기준으로 테이블을 분할
        
        <img width="406" alt="image (9)" src="https://github.com/user-attachments/assets/7e2d1cf8-8339-4443-b801-b4cafe33aaa8">
    
    파티셔닝을 할 땐 여러가지 방법이 있음.
    
    - Key range partitioning : 날짜, 숫자 등 범위를 기준으로 테이블을 수평분할하여 관리함으로써 데이터 조회, 보관, 삭제 등이 간편해짐
    - Hash partitioning : 해시값을 기준으로 데이터를 분할하여 보관
        
        → Key range 파티셔닝에서 데이터 불균형 문제를 해결할 수 있음
        
        → 대용량 데이터 분산처리가 가능해짐
        
    - List partitioning : 특정한 속성(attribute) 또는 컬럼(column)의 값을 기준으로
    테이블을 수평분할하여 관리
- `테이블 추가`
    - 중복 테이블 추가 : 동일한 테이블 구조를 중복하여 원격조인을 제거
    - 통계 테이블 추가 : SUM, AVG 등을 미리 수행하여 계산
    - 이력 테이블 추가 : 마스터 테이블에서 자주 조회되는 레코드를 중복하여 테이블 추가
    - 부분 테이블 추가 : 자주 이용하는 컬럼을 모아놓은 별도의 테이블 추가

### 속성 반정규화

- `중복 칼럼 추가` : 조인 감소를 위해 중복된 컬럼을 추가
- `파생 칼럼 추가` : 미리 값을 계산하여 칼럼에 보관
- `이력 테이블 칼럼 추가` : 대량의 이력 데이터를 처리할 때 기능성 칼럼(최근값 여부, 시작과 종료일자 등)을 추가
- `PK에 의한 칼럼 추가` : 여러 칼럼으로 이루어진 PK를 가진 테이블을 조인할 경우 단순성을 위해서 인공키를 PK로 지정하고 활용
- `응용시스템 오작동을 위한 칼럼 추가` : 이전 데이터를 임시적으로 중복하여 보관
